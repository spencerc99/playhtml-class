## Let's create a web ring together!

What is a [web ring](https://en.wikipedia.org/wiki/Webring)? A web ring is a collection of websites linked together in a circular structure. Each site points to another site, creating a continuous loop.

![A diagram of a web ring](/images/Webringwork.png)

The early web was full of separate personal homepages. A web ring stitched those independent places into a shared path without turning them into one platform.

Our class ring has two related layers:

1. The **shared charm**: each submitted project becomes a circular consumer in the Showcase that can share an interaction with an element on its owner's site.
2. The **ring embed**: one script lets participants display an expandable directory of all class websites on their own site.

### The one idea to teach

PlayHTML [shared elements](https://playhtml.fun/docs/advanced/shared-elements/) have:

- a **source** on the participant's site
- a **consumer** in the class Showcase
- the same PlayHTML capability on both sides

They share state, but they do not need the same HTML, image, CSS, or layout.

The documentation can be reduced to three rules:

1. A source has a stable `id`, `shared`, and one or more PlayHTML capabilities.
2. A consumer points to `domain/optional-path#elementId` with `data-source`.
3. Every capability you want to share must exist on both source and consumer. Their tags, children, classes, and styling may be completely different.

Here is the basic example from the PlayHTML docs:

```html
<!-- Source on thissite.com -->
<div id="couch" shared can-move>🛋️</div>

<!-- Consumer on anothersite.com -->
<div data-source="thissite.com#couch" can-move>🪑</div>
```

The source is a couch and the consumer is a chair. Their markup looks different, but their `can-move` position is shared.

Our ring follows the same pattern:

```html
<!-- Source on the participant's site -->
<img id="my-ring-charm" shared can-toggle src="/lamp.png" alt="A lamp" />

<!-- Consumer created safely by the class Showcase -->
<img
  data-source="student.example#my-ring-charm"
  can-toggle
  src="https://student.example/circle.png"
  alt=""
/>
```

The **circle image submitted in the form is the consumer element**. The participant keeps complete control over the source element and code on their own site.

### 1. Match the source capabilities

The capability is the kind of state shared between the two sites. It is not the visual style.

| Capability   | Shared state        | Participant can customize                          |
| ------------ | ------------------- | -------------------------------------------------- |
| `can-toggle` | on or off           | colors, images, visibility, sound, local animation |
| `can-spin`   | rotation            | what spins and what the rotation means             |
| `can-grow`   | scale               | what grows and how the surrounding page responds   |
| `can-hover`  | live hover presence | what responds when someone hovers either copy      |
| `can-move`   | dragged position    | the object, its appearance, and its surroundings   |

For example, two students can both use `can-toggle`: one might light a lamp while another reveals a secret garden. The shared contract is the same; the effect is not. The form asks for the capability because the Showcase must put that matching attribute on the circle consumer—not to prescribe the participant's design.

PlayHTML itself also supports `can-mirror`, `can-duplicate`, and custom `can-play`. We do not infer those from a submission because they carry DOM structure, duplication targets, or a custom data schema and renderer. Participants may use them freely on their own sites. Bringing them into the Showcase requires a specific, reviewed adapter rather than executing submitted code.

### 2. Add a source to your site

This is the smallest complete toggle example:

```html
<img
  id="my-ring-charm"
  shared
  can-toggle
  src="/lamp.png"
  alt="Turn the lamp on or off"
/>

<style>
  #my-ring-charm {
    filter: grayscale(1);
    transition: 300ms;
  }

  /* PlayHTML adds .toggled when the shared state is on. */
  #my-ring-charm.toggled {
    filter: grayscale(0) drop-shadow(0 0 20px gold);
  }
</style>

<script type="module">
  import { playhtml } from 'https://unpkg.com/playhtml';

  playhtml.init();
</script>
```

To try a different capability, keep the stable ID and replace `can-toggle` with `can-spin`, `can-grow`, `can-hover`, or `can-move`.

You can continue editing the HTML, images, CSS, and scripts on your site after joining the ring. You do not need to resubmit unless you change the source page URL, element ID, or shared capability.

### 3. Publish, then submit

Deploy the project before adding it to the Showcase. The source must exist at a public URL.

In the submission form, add:

1. Your project details and public URL
2. The emoji, glow color, and optional **circle image URL** for the consumer
3. The exact page URL containing your source element
4. The source's stable element ID, such as `my-ring-charm`
5. The same shared capability used by the source

The form generates a source snippet for comparison. It stores configuration, not participant JavaScript.

### 4. Test both directions

1. Open the participant's deployed site in one window.
2. Open the class Showcase in another window.
3. Interact with the source and watch the circle update.
4. Interact with the circle and watch the source update.

If it does not connect, check:

- Is the source deployed at a public URL rather than only available in a private development environment?
- Does the submitted page include the exact path? `student.example/room` and `student.example/` are different PlayHTML rooms.
- Does the stable ID match exactly?
- Do source and consumer use the same capability?
- Does the source include `shared`?
- Does the page initialize PlayHTML once?

### 5. Keep shaping your place

The ring is not a final upload. Participants can:

- keep changing and redeploying all code on their own site
- customize how their shared state is represented locally
- use a different source image from the class circle image
- return to **Your submissions → Edit** to change their circle, metadata, source URL, ID, or capability

The Showcase never executes submitted code. This lets each site remain expressive while the class ring stays safe and structurally consistent.

### 6. Put the whole ring on your site

The shared charm connects one element to the Showcase. This separate embed displays the directory of class sites on any participant website:

```html
<script
  type="module"
  src="https://class.playhtml.fun/class-webring.js"
  data-variant="peek"
></script>
```

After deployment, the script lives at [`/class-webring.js`](/class-webring.js). It derives the Showcase registry from the domain serving the script and subscribes read-only.

Choose either visual treatment:

- `data-variant="peek"` keeps a small piece of the ring in the bottom-right corner. Hovering or focusing it spins the image orbit into view. This is the class-site default.
- `data-variant="expandable"` restores the larger button and fullscreen image field. It is titled **Benches for the Internet** and does not display a project count.

For the expandable option, change only the attribute:

```html
<script
  type="module"
  src="https://class.playhtml.fun/class-webring.js"
  data-variant="expandable"
></script>
```

The class app chooses the script URL automatically. During local development it loads `/class-webring.js` from the current development origin. A production build loads the canonical script above from `class.playhtml.fun`. The resolver lives in `src/lib/classWebringScript.ts`, so previewing and deploying do not require hand-editing a URL.

For a separate staging deployment, use that deployment's origin instead:

```html
<script
  type="module"
  src="https://YOUR-PREVIEW-DOMAIN/class-webring.js"
></script>
```

Visit the hidden [`/webring-demo`](/webring-demo) route to see a pretend independent website load this exact script. The demo uses sample circles only when the real registry is empty.

### Teaching plan (25–30 minutes)

**5 minutes — Source and consumer.** Show the couch/chair example. Ask what is the same and what is different.

**5 minutes — Customize one toggle.** Demonstrate the lamp source and change only its `.toggled` CSS to show that capability and visual effect are separate.

**10 minutes — Make and publish.** Each participant chooses a charm, adds a capability, and deploys it.

**5 minutes — Submit and connect.** Add the exact URL, ID, and matching capability to the form.

**5 minutes — Test in pairs.** Open the source and Showcase side by side and interact in both directions.

**5 minutes — Install the directory.** Paste the one-tag ring embed into one participant site and visit a circle in its orbit.

Questions for the group:

- What state did you choose to let travel between sites?
- How does the same shared state take on a different meaning in each design?
- What should remain under the control of each independent site?
