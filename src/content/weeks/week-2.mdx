## How does the web know who's on the bench?

The internet is a network of computers communicating through a shared set of rules, or protocols. Despite its ethereal reputation, the internet is technically physical. It relies heavily on an underwater and underground telecommunications infrastructure originally laid down in the 20th century, deeply rooted in the geopolitical history of colonialism and the Cold War.

![1901 Eastern Telegraph cables](/images/1901_Eastern_Telegraph_cables.png)
[Eastern Telegraph Company Undersea Cables (1901)](https://commons.wikimedia.org/wiki/File:1901_Eastern_Telegraph_cables.png)

It can be very fragile sometimes (for instance, when an underwater cable is damaged, it can disrupt communication across the globe). When we build real-time digital spaces today, our software code runs directly on top of these historical, physical pathways.

![Shark Eating Undersea Cable](/images/sddefault.jpg)
[Sharks are Attacking the Internet! - Youtube](https://www.youtube.com/watch?v=o0mxdCljXwA)

The web is built on a request-response model, which means that computers (clients) send requests to other computers (servers) and wait for a response. A server is basically a computer that stores and serves content to other computers. When you visit a website, your computer sends a request to the server where the website is hosted, and the server responds by sending back the requested content.

![An image showing a computer that has a sticky note on it that says "this machine is a server, do not power down!!"](/images/do-not-turn-off.jpg)
[This computer is a server. DO NOT SHUT IT DOWN!!](https://blog.perguth.de/posts/2024-12-16-this-computer-is-a-server-do-not-shut-it-down/)

For instance, when we visit a site like [playhtml.fun](https://playhtml.fun), our computer sends a request to the server where the site is hosted, and the server responds by sending back the HTML, CSS, and JavaScript files that make up the site.

## Real-Time Communication & Persistence

This model (called the request-response model) works perfectly for loading static pages, but it has a major limitation for creating communal spaces: the server only knows about you the exact second you ask for something. Once it sends back those files, it completely hangs up and forgets you are there. It has no idea you are still sitting on the website looking at the screen.

To create a shared web experience where you can see other people in real-time, this one-way, request-response model breaks down. If the web only updates when you pull data via a request, how does your browser know when someone else has just sat down on the bench next to you?

To solve this, we have to change to a completely different protocol, Web Sockets, which allows for two-way communication between the client and the server. Instead of making a request and waiting for a response, the client and server can send messages to each other at any time after they perform an initial "handshake". The server can push updates to the client without the client having to ask for them, and the client can send messages to the server without waiting for a response. This allows for real-time communication and collaboration, which is essential for creating spaces on the web that feel inhabited by other people live.

![Web Socket Protocol Diagram](/images/Websocket_connection.png)

And to get your actions to stick around even after you refresh the page, we need to "persist" that state and data somewhere that it can be retrieved, which requires a **database**. This is a secure location that saves the data and allows you to retrieve it later. These are often relational or key-value stores that allow you to store and retrieve data quickly and efficiently.

Setting up these systems is more complicated than hosting a static website. You cannot just use [GitHub Pages](https://pages.github.com/) or [Netlify](https://www.netlify.com/) to host a Web Socket server, because they are designed for static sites. Instead, you need to use a hosting service that supports Web Sockets with a database, such as [Heroku](https://www.heroku.com/), [AWS](https://aws.amazon.com/), or [DigitalOcean](https://www.digitalocean.com/). You also need to write server-side code to handle the Web Socket connections and manage the state of the communal space.

This is why using a library like playhtml is so helpful. The library hosts the infrastructure for you, so you don't have to worry about setting up your own. It also provides a simple API for managing the state of the communal space and synchronizing it across all connected clients.

![How playhtml syncs element state between browsers](/images/playhtml-sync-diagram.png)

playhtml stores data for every marked element on your page by their `id` (this is why every element needs a unique ID to know which element is which!). When you change something (move a chair, toggle a lamp, type in a textarea), that is changing some data (the lamp is `on` or `off`, the chair has an `x` and `y` position, etc.) that syncs up to playhtml's server, which saves it and pushes updates to everyone else on the same page over the open WebSocket connection.

Under the hood, playhtml relies on [Cloudflare](https://www.cloudflare.com/), a massive global network infrastructure. Instead of spending weeks configuring backend servers and WebSocket protocols, you just drop a small script into your HTML file. The infrastructure handles the heavy lifting, turning your static webpage into a multiplayer space instantly.

## Live Cursors

The first thing we can do to make our communal space feel more alive is to show where other people are on the page. This ["live cursor" feature](https://playhtml.fun/docs/data/presence/cursors/) is already built-in the library and will allow you to see where other people are looking, clicking, and interacting with the page in real-time.

```html
<script type="module">
  import { playhtml } from 'https://unpkg.com/playhtml';

  playhtml.init({
    cursors: {
      enabled: true,
    },
  });
</script>
```

### Config: development mode

When you are building and debugging, it can be helpful to initialize playhtml with development mode enabled. This gives you a more debugging-friendly setup while you iterate locally.

```html
<script type="module">
  import { playhtml } from 'https://unpkg.com/playhtml';

  playhtml.init({
    developmentMode: true,
  });
</script>
```

## Custom Behaviors

Last week, we learned how to use the built-in attributes like `can-move`, `can-spin`, `can-grow`, and `can-toggle` to create communal spaces. This week, we will learn how to create more custom behaviors using `can-mirror`.

We will have to write some JavaScript code to create these custom behaviors. Javascript is a programming language that allows you to add interactivity and dynamic behavior to your web pages. Unlike HTML and CSS, which are [declarative languages](https://en.wikipedia.org/wiki/Declarative_programming) that describe the structure and style of a web page, JavaScript is an [imperative language](https://en.wikipedia.org/wiki/Imperative_programming) that allows you to write instructions for the browser to execute.

<CodeDemo demo={<ButtonClickDemo />}>

```html
<button id="my-button">Click me!!</button>
```

```css
#my-button {
  background-color: blue;
  color: white;
  padding: 10px 20px;
  border: none;
  border-radius: 5px;
  cursor: pointer;
}
```

```javascript
// select the button element by its ID
const button = document.getElementById('my-button');

// add an event listener to the button that listens for a click event
button.addEventListener('click', () => {
  // when the button is clicked, show an alert message
  alert('Button clicked!');
  // you can also change the button's text or style here if you want
  button.textContent = 'Clicked!';
  // change the button's css style
  button.style.backgroundColor = 'red';
});
```

</CodeDemo>

This means that you can use [JavaScript](https://web.dev/learn/javascript) to manipulate the DOM (Document Object Model) of your web page, respond to user events, and communicate with the server, but also Javascript is not as forgiving as HTML and CSS. It doesn't interpret your code if you make a mistake, and it will throw an error instead. This means that you have to be very careful with your syntax and logic when writing JavaScript code, and you may have to debug your code with the console if it doesn't work as expected.

### Arrow Functions

You will see arrow functions a lot in this class. They are just a shorter way to write functions. We can write a function like this:

```javascript
// regular function
button.addEventListener('click', function () {
  console.log('clicked');
});

// arrow function (same behavior here)
button.addEventListener('click', () => {
  console.log('clicked');
});
```

There are many many things you can do with JavaScript, but for this class, we will focus on using it to create custom behaviors for our communal spaces. Particularly, we'll be looking at:

- how to respond to [user events](https://www.w3schools.com/jsref/dom_obj_event.asp) like clicks, mouse movements, and keyboard inputs
- how to dynamically change the content of my HTML elements
- how to dynamically change the style (CSS) of my HTML elements
- how to add and remove elements from the DOM

### Can-mirror

The `can-mirror` attribute is the easiest way to make a custom element collaborative, because you don't model any data yourself: it mirrors the element's own state. It automatically syncs every attribute of the original element (position, rotation, scale, color) and the internal state of form elements (text areas, inputs, etc.), so whatever is on your screen shows up on everyone else's.

#### syncing the content

<CodeDemo demo={<MirrorTextareaDemo />}>

```html
<textarea can-mirror id="text-area" rows="4"></textarea>
```

</CodeDemo>

#### syncing the style

It also syncs styling. Because `can-mirror` watches every attribute, anything you change on the element — including its inline `style` — shows up for everyone. Here, a button paints a rectangle a random color, and that color follows to every other screen:

<CodeDemo demo={<MirrorColorDemo />}>

```html
<div can-mirror id="color-rect"></div>
<button id="color-btn">random color</button>
```

```javascript
const rectangle = document.getElementById('color-rect');
const button = document.getElementById('color-btn');
button.addEventListener('click', () => {
  // change the style locally; can-mirror syncs it to everyone
  const hue = Math.floor(Math.random() * 360);
  rectangle.style.background = `hsl(${hue}, 80%, 70%)`;
});
```

</CodeDemo>

#### syncing the children (add or remove elements)

This can be useful for creating shared text areas, collaborative drawing spaces, or any other element that you want to keep in sync across clients. It also keeps the _children_ of an element in sync as you add and remove them.

<CodeDemo demo={<BunnyMirrorDemo />} inline>

```html
<button id="clone-bunny">clone bunny</button>
<button id="remove-bunny">remove bunny</button>
<div can-mirror id="bunny-pen"></div>
```

```javascript
const pen = document.getElementById('bunny-pen');
const btnClone = document.getElementById('clone-bunny');

btnClone.onclick = () => {
  const bunny = document.createElement('img');
  bunny.id = 'bunny-' + pen.children.length;
  bunny.src = '/pixel-bunny.png';
  pen.appendChild(bunny);
};

btnRemove.onclick = () => {
  pen.lastChild.remove();
};
```

</CodeDemo>

Check out the full playground for can-mirror [here](https://playhtml.fun/docs/advanced/mirror-playground/).

`can-mirror` is the right tool when the DOM is the shared state: whatever's on your screen should be on everyone's screen, with no logic in between.

When you need more flexibility, `can-play` allows you to define how an element should behave based on the data you're saving. The complex part is that you have to think about and define your data up front. In return, you have the expressiveness to do anything in response to what someone does. We'll cover this next week but feel free to peek and poke around on the docs if you want to try it out now.

### A peek at `can-play`

We can start with something simple — a visit counter. One number changes: the count starts at `0` and goes up as people arrive.

```html
<div can-play id="visit-counter">0</div>
<script>
  const visitCounter = document.getElementById('visit-counter');

  // 1. the data this element stores, and what it starts as
  visitCounter.defaultData = { visits: 0 };

  // 2. how that data turns into what people see
  visitCounter.updateElement = ({ element, data }) => {
    element.textContent = data.visits;
  };

  // 3. bump the count by one every time the page loads
  visitCounter.onMount = ({ setData }) => {
    setData((data) => {
      data.visits += 1;
    });
  };
</script>
```

`defaultData` is the starting state. `updateElement` runs whenever that data changes and updates what people see. `onMount` lets you do any extra set up when the page is loaded.

We'll go deeper with `can-play` next week. For now, there should be plenty to explore with `can-mirror`.
