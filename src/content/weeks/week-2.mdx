## How does the web know who's on the bench?

- The internet is a network of computers communicating through a shared set of rules, or protocols. Despite its ethereal reputation, the internet is technicalky physical. It relies heavily on an underwater and underground telecommunications infrastructure originally laid down in the 20th century, deeply rooted in the geopolitical history of colonialism and the Cold War.

![1901 Eastern Telegraph cables](/images/1901_Eastern_Telegraph_cables.png)

It can be very fragile sometimes (for instance, when an underwater cable is damaged, it can disrupt communication across the globe). When we build real-time digital spaces today, our software code runs directly on top of these historical, physical pathways.

![Shark Eating Undersea Cable](/images/sddefault.jpg)

The web is built on a request-response model, which means that computers (clients) send requests to other computers (servers) and wait for a response. A server is basically a computer that stores and serves content to other computers. When you visit a website, your computer sends a request to the server where the website is hosted, and the server responds by sending back the requested content.

![An image showing a computer that has a sticky note on it that says "this machine is a server, do not power down!!"](/images/do-not-turn-off.jpg)

For instance, when we visit a site like [playhtml.com](https://playhtml.com), our computer sends a request to the server where the site is hosted, and the server responds by sending back the HTML, CSS, and JavaScript files that make up the site.

## Real-Time Communication

This model (called the request-response model) works perfectly for loading static pages, but it has a major limitation for creating communal spaces: the server only knows about you the exact second you ask for something. Once it sends back those files, it completely hangs up and forgets you are there. It has no idea you are still sitting on the website looking at the screen.

To create a shared web experience where you can see other people in real-time, this one-way, request-response model breaks down. If the web only updates when you pull data via a request, how does your browser know when someone else has just sat down on the bench next to you?

To solve this, we have to change to a completely different protocol, Web Sockets, which allows for two-way communication between the client and the server. Instead of making a request and waiting for a response, the client and server can send messages to each other at any time after they perform an initial "handshake". The server can push updates to the client without the client having to ask for them, and the client can send messages to the server without waiting for a response. This allows for real-time communication and collaboration, which is essential for creating communal spaces on the web.

![Web Socket Protocol Diagram](/images/Websocket_connection.png)

But setting up a Web Socket server is a bit more complicated than just hosting a static website. You cannot just use [GitHub Pages](https://pages.github.com/) or [Netlify](https://www.netlify.com/) to host a Web Socket server, because they are designed for static sites. Instead, you need to use a hosting service that supports Web Sockets, such as [Heroku](https://www.heroku.com/), [AWS](https://aws.amazon.com/), or [DigitalOcean](https://www.digitalocean.com/). You also need to write server-side code to handle the Web Socket connections and manage the state of the communal space.

This is why using a library like playHTML is so helpful. The library directly hosts a Web Socket server for you, so you don't have to worry about setting up your own. It also provides a simple API for managing the state of the communal space and synchronizing it across all connected clients.

Under the hood, playhtml currently relies on [Cloudflare](https://www.cloudflare.com/), a massive global network infrastructure. Instead of spending weeks configuring backend servers and WebSocket protocols, you just drop a small script into your HTML file. The infrastructure handles the heavy lifting, turning your static webpage into a multiplayer space instantly.

## Custom Behaviors

Last week, we learned how to use the built-in attributes like `can-move`, `can-spin`, `can-grow`, and `can-toggle` to create communal spaces. This week, we will learn how to create more custom behaviors using `can-duplicate`, `can-mirror` and `can-play` to create more complex interactions and experiences.

We will have to write some JavaScript code to create these custom behaviors. Javascript is a programming language that allows you to add interactivity and dynamic behavior to your web pages. Unlike HTML and CSS, which are [declarative languages](https://en.wikipedia.org/wiki/Declarative_programming) that describe the structure and style of a web page, JavaScript is an [imperative language](https://en.wikipedia.org/wiki/Imperative_programming) that allows you to write instructions for the browser to execute.

```html
<button id="my-button">Click me</button>
```

```css
#my-button {
  background-color: blue;
  color: white;
  padding: 10px 20px;
  border: none;
  border-radius: 5px;
  cursor: pointer;
}
```

```javascript
const button = document.getElementById('my-button');
button.addEventListener('click', () => {
  alert('Button clicked!');
});
```

This means that you can use JavaScript to manipulate the DOM (Document Object Model) of your web page, respond to user events, and communicate with the server, but also Javascript is not as forgiving as HTML and CSS. It doesn't interpret your code if you make a mistake, and it will throw an error instead. This means that you have to be very careful with your syntax and logic when writing JavaScript code, and you may have to debug your code with the console if it doesn't work as expected.

### Can-mirror

The `can-mirror` attribute allows you to sync the state of an element across clients. It auto-syncs every attribute of the original element, including position, rotation, scale, and color.

```html
<textarea can-mirror id="text-area" rows="4"></textarea>
```

This can be useful for creating shared text areas, collaborative drawing spaces, or any other element that you want to keep in sync across clients.

```html
<ul can-mirror id="guestbook">
  <li>first</li>
</ul>
<button id="add-entry">add entry</button>
```

```javascript
const guestbook = document.getElementById('guestbook');
const addEntryButton = document.getElementById('add-entry');
addEntryButton.onclick = function () {
  const newEntry = document.createElement('li');
  newEntry.textContent = 'new entry';
  newEntry.id = 'entry-' + (guestbook.children.length + 1);
  guestbook.appendChild(newEntry);
};
```
